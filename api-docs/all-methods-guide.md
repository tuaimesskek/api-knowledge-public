# Путеводитель по методам Swagger API

Это объяснения **всех операций**, описанных в опубликованных Swagger-спецификациях репозитория: основного API и ЭДО API. Для каждого метода перечислены назначение, параметры, поля тела запроса, описание успешного ответа и ошибки, когда такие данные опубликованы.

Сначала выберите предметный раздел, затем найдите точное сочетание HTTP-метода и URL. Поля без признака обязательности в таблицах необязательны по схеме запроса, но бизнес-правила метода могут добавлять условия. Проверяйте описание метода и права пользователя.

### Как читать карточку метода

- **Путь** показывает адрес операции. Значения в фигурных скобках, например `{offerId}`, заменяются на реальные ID.
- **Path-параметр** входит в адрес, а **query-параметр** добавляется после `?`, например `?page=1`. Несколько параметров соединяются через `&`.
- **Header** передаётся в заголовке HTTP-запроса. Для многих методов это `ZakupayToken`; конкретный метод может иметь свои требования.
- **Тело запроса** передаётся после заголовков, обычно в формате JSON. В карточках отмечены типы полей и обязательность, если это указано схемой.
- `GET` чаще читает данные, `POST` чаще создаёт объект или запускает действие, `PUT`/`PATCH` меняют данные, `DELETE` удаляет. Это только общее правило: конкретный сценарий задаётся описанием endpoint, и в Swagger встречаются исключения.
