# Проекты

Методы этого раздела сгруппированы по назначению. Для каждого метода указаны контрактные сведения из Swagger; поля и ограничения, которых нет в спецификации, здесь не предполагаются.

Источники:

- `openapi/swagger-core.yaml`

## Кратко по методам

| Метод | Для чего | Как указать объект и данные | Что меняет / возвращает |
|---|---|---|---|

## `POST /api/v1/projects`

**Название в Swagger:** Создание проекта.

**Описание Swagger:**

Пользователь, пытающийся создать проект, должен иметь право `REFBOOKS_PROJECTS_CREATE` которое входит в роли **Проекты.Создать** и **Роль сотрудника.Администратор**

Добавление проектов осуществляется путем добавления проектов по уровням  иерархии, изначально добавляются проекты верхнего уровня иерархии, затем проекты уровнем следующим ниже.

Например, если у Вас стандартная иерархия проектов *Объект* - *Договор* - *Вид  работ*. Сначала Вы добавляете уровень проекта типа *Объект*, после  чего добавляете проекты типа *Договор*, затем добавляете проекты типа *Вид работ*.

### Параметры

| Где | Имя | Обязательный | Тип | Описание |
|---|---|---:|---|---|
| query | `format` | Нет | string | Возможность задать формат ответа API через `GET` параметр. Любые недопустимые значения параметра игнорируются и используется `json` (см. [Формат ответа](#response-format)). |
| query | `isoDate` | Нет | string | Возможность задать формат представления дат в ответе API как *ISO 8601*. Любые значения параметра игнорируются, необходимо лишь наличие параметра (см. [Формат представления дат](#date-format)). |
| header | `ZakupayToken` | Да | string | Токен для авторизации пользователя в системе, значение которого можно получить в личном кабинете пользователя на вкладке "Безопасность" в разделе "Токены для приложений, интегрированных с порталом". |

### Тело запроса

Обязательность тела явно не указана.

Формат: `application/json`.

| Поле | Обязательное | Тип | Описание |
|---|---:|---|---|
| `name` | Да | string | Наименование проекта. |
| `externalId` | Нет | string | Внешний идентификатор проекта. |
| `cadastralNumber` | Нет | string | Кадастровый номер ЗУ проекта |
| `description` | Нет | string | Комментарий - описание проекта. |
| `type` | Да | object | Информация по типу проекта. |
| `template` | Нет | object | Информация по шаблону проекта. |
| `parent` | Нет | object | Информация по родительскому проекту. |
| `responsible` | Нет | object | Ответственный за снабжение на проекте. |
| `orderCreators` | Нет | object | Пользователи имеющие право создавать заявки по указанному проекту. |
| `orderAcceptors` | Нет | object | Пользователи, являющиеся акцепторами для заявок по указанному проекту. |
| `spectators` | Нет | object | Пользователи, являющиеся наблюдателями по указанному проекту. |
| `offerAcceptors` | Нет | object | Пользователи, являющиеся акцепторами счетов по заявкам по указанному проекту. |
| `budgetAcceptors` | Нет | object | Пользователи, являющиеся акцепторами бюджетов по указанному проекту. |
| `paymentPlanners` | Нет | object | Пользователи, отвечающие за планирование платежей в счетах по указанному проекту. |
| `deliveryAcceptors` | Нет | object | Пользователи, отвечающие за принятие доставок по счетам по указанному проекту. |
| `additionalDataJson` | Нет | object | Пользовательские JSON-данные проекта. В данном поле могут быть указаны различные данные в формате JSON, например поля со значениями необходимыми для обратной передачи в интегрируемую систему. |

Swagger описывает успешный ответ `200`.

Формат: `application/json`.

Структура успешного ответа не раскрыта на верхнем уровне операции.

### Ошибки и другие ответы

## `GET /api/v1/projects`

**Название в Swagger:** Получение информации по проектам.

**Описание Swagger:**

Выдает список проектов с дополнительной информацией (номер и размер запрошенной страницы, количество проектов в ответе).
 Метод предоставляет возможность запрашивать коллекцию проектов постранично, максимальное количество проектов на странице задается параметром pageSize (стандартное значение = 10, максимальное значение = 100), для загрузки страниц используется параметр page. Также доступны различные способы по фильтрации проектов.

__Метод доступен если__:
пользователь

    - авторизован,

    - имеет доступ к системе,

    - состоит в какой-либо компании,

    - имеет право REFBOOKS_PROJECTS (входит в роль Проекты. Просмотр)

### Параметры

| Где | Имя | Обязательный | Тип | Описание |
|---|---|---:|---|---|
| query | `page` | Нет | integer[int64] | Номер страницы. |
| query | `pageSize` | Нет | integer[int64] | Задает размер выдаваемой страницы, максимальное значение - **100** |
| query | `isoDate` | Нет | string | Возможность задать формат представления дат в ответе API как **ISO 8601**. Любые значения параметра игнорируются, необходимо лишь наличие параметра (см. [Формат представления дат](#date-format)). |
| query | `ids` | Нет | integer[int64] | Список `id` проектов, которые будут получены в результате запроса. Можно передать несколько параметров **(ids=1&ids=2&ids=3)** |
| query | `include` | Нет | string | Позволяет получить иерархию проектов. Параметры: <ul><br>  <li><br>    <b>"hierarchy"</b> - вместе с каждым проектом передается его родитель (максимальная глубина иерархии настраивается опцией **max_project_depth**).<br>  </li><br>  <li><br>    <b>"children"</b> - вместе с каждым проектом передаются его дочерние проекты (максимальная глубина иерархии настраивается опцией **max_project_depth**)<br>  </li><br></ul> |
| query | `excludedIds` | Нет | integer[int64] | Список `id` проектов, которые нужно исключить из выборки. Можно передать несколько параметров (**excludedIds=242&excludedIds=241**) |
| query | `externalId` | Нет | string | Внешний `id` проекта, для поиска проекта по внешнему `id` |
| query | `updatedTimeTo` | Нет | integer[int64] | Время последнего обновления проектов в `UNIX`или `ISO 8601` - формате, в результат попадут проекты, обновленные до этой даты |
| query | `updatedTimeFrom` | Нет | integer[int64] | Время последнего обновления проектов в `UNIX` или `ISO 8601` - формате, в результат попадут проекты, обновленные после этой даты |
| query | `changeActiveBudgetDateFrom` | Нет | integer[int64] | Время последнего обновления активности бюджета внутри проекта в `UNIX` или `ISO 8601` - формате. В результат попадут проекты, обновленные после этой даты. |
| query | `changeActiveBudgetDateTo` | Нет | integer[int64] | Время последнего обновления активности бюджета внутри проекта в `UNIX` или `ISO 8601` - формате. В результат попадут проекты, обновленные до этой даты |
| header | `ZakupayToken` | Да | string | Токен для авторизации пользователя в системе, значение которого можно получить в личном кабинете пользователя на вкладке "Безопасность" в разделе "Токены для приложений, интегрированных с порталом". |

### Успешный ответ

Swagger описывает успешный ответ `200`.

Формат: `application/json`.

| Поле | Обязательное | Тип | Описание |
|---|---:|---|---|
| `count` | Да | integer[int64] | Количество выданных проектов |
| `page` | Да | integer[int64] | Номер запрошенной страницы |
| `pageSize` | Да | integer[int64] | Размер запрошенной страницы |
| `pagesCount` | Да | integer[int64] | Количество выданных страниц (всегда 1) |
| `projects` | Да | object | Информация по проекту |
| `totalCount` | Да | integer[int64] | Количество выданных проектов |

### Ошибки и другие ответы

- `400` — Bad request
- `401` — Unauthorized
- `403` — Forbidden
- `500` — Internal server error
