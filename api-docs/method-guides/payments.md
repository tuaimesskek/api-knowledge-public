# Платежи

Методы этого раздела сгруппированы по назначению. Для каждого метода указаны контрактные сведения из Swagger; поля и ограничения, которых нет в спецификации, здесь не предполагаются.

Источники:

- `openapi/swagger-core.yaml`

## `GET /api/v1/payments`

**Название в Swagger:** Получение списка платежей.

**Описание Swagger:**

Позволяет получить список платежей.
 Метод предоставляет возможность запрашивать коллекцию платежей по счетам постранично, максимальное количество платежей на странице задается параметром `pageSize` (стандартное значение = **10**, максимальное значение = **100**), для загрузки страниц используется параметр `page`. Также доступны различные способы по фильтрации платежей по счетам.

 __Метод доступен если пользователь__:

      - авторизован;

      - имеет доступ к системе;

      - имеет право `OFFERS`;

| query | `paymentDateFrom` | Нет | string | Возможность отфильтровать получаемые платежи по тем, что были оплачены в заданную дату или после неё. Значение передавать в формате *ISO 8601* в виде *yyyy-MM-dd*. Допустимо указывать только одно значение. |

### Успешный ответ

Swagger описывает успешный ответ `200`.

Формат: `application/json`.

| Поле | Обязательное | Тип | Описание |
|---|---:|---|---|
| `result` | Нет | boolean | Запрос завершился успешно. |
| `count` | Нет | integer | Фактическое кол-во элементов, которые были возвращены. Например, может быть запрошена страница размером 25, а вернётся 11. | `page` | Нет | integer | Номер запрошенной страницы, совпадает с тем, что было передано в *GET*-параметре (либо взято по умолчанию, если не было задано). |
| `pageSize` | Нет | integer | Размер запрошенной страницы, совпадает с тем, что было передано в *GET*-параметре (либо взято по умолчанию, если не было задано или задано некорректно). |
| `pagesCount` | Нет | integer | Общее кол-во страниц счетов, которые могут быть запрошены согласно заданной фильтрации и размера страницы. |

## `PUT /api/v1/offers/{offerId}/payments/{offerPaymentId}`

**Название в Swagger:** Обновление платежа по счету.

**Описание Swagger:**

Метод позволяет изменить данные по платежу.

Пользователь, пытающийся обновить платеж, должен иметь право `OFFERS_PAY`.

Так же должен быть соблюден ряд условий:
- запрос счёта должен быть выслан компанией пользователя ИЛИ
- счёт выставлен на банковский счёт компании пользователя ИЛИ
- среди заявок, связанных со счётом есть заявки компании пользователя.
- изменяемый платеж должен быть принят к оплате.

### Параметры

| Где | Имя | Обязательный | Тип | Описание |
|---|---|---:|---|---|
| query | `format` | Нет | string | Возможность задать формат ответа API через `GET` параметр. Любые недопустимые значения параметра игнорируются и используется `json` (см. [Формат ответа](#response-format)). |
| query | `isoDate` | Нет | string | Возможность задать формат представления дат в ответе API как `ISO 8601`. Любые значения параметра игнорируются, необходимо лишь наличие параметра (см. [Формат представления дат](#date-format)). |
| path | `offerId` | Да | integer[int64] | Идентификатор счета, по которому необходимо обновить платеж |
| path | `offerPaymentId` | Да | integer[int64] | Идентификатор платежа. Платеж должен быть принят к оплате |
| header | `ZakupayToken` | Да | string | Токен для авторизации пользователя в системе, значение которого можно получить в личном кабинете пользователя на вкладке "Безопасность" в разделе "Токены для приложений, интегрированных с порталом". |

### Тело запроса

Обязательность тела явно не указана.

Формат: `application/json`.

| Поле | Обязательное | Тип | Описание |
|---|---:|---|---|
| `amount` | Нет | number | Сумма платежа. Должна быть больше нуля и меньше текущей суммы платежа. Если валюта счета не отличается от основной валюты,  то автоматически проставлаяется так же и amountInMainCurrency. Если amount больше текущей суммы платежа, то отправляется предупреждение ответсвенному по заявке счета. |
| `amountInMainCurrency` | Нет | number | Сумма платежа в основной для пользователя валюте. Проставлаяется только если валюта счета отличается от основной. Должна быть больше нуля |
| `date` | Да | string | Фактическая дата выполнения платежа |
| `number` | Да | string | Номер платежа. Максимальное количетсво символов - 256 |

### Успешный ответ

Swagger описывает успешный ответ `200`.

Формат: `application/json`.

| Поле | Обязательное | Тип | Описание |
|---|---:|---|---|
| `result` | Нет | boolean | Запрос завершился успешно. |
| `offerPayment` | Нет | object | Информация об измененном платеже |

### Ошибки и другие ответы

- `400` — Bad Request
- `404` — Not Found
- `403` — Forbidden


## `DELETE /api/v1/offers/{offerId}/payments/{offerPaymentId}`

**Название в Swagger:** Удаление платежа по счету.

**Описание Swagger:**

Метод позволяет удалить платёж.

Пользователь, пытающийся удалить платёж, должен иметь права `OFFERS_PAY` и `OFFERS_PAY_DELETE`.

Так же необходимо, чтобы платёж принадлежал указанному счёту.

### Параметры

| Где | Имя | Обязательный | Тип | Описание |
|---|---|---:|---|---|
| path | `offerId` | Да | integer[int64] | Идентификатор счета, по которому необходимо обновить платеж |
| path | `offerPaymentId` | Да | integer[int64] | Идентификатор платежа. Платеж должен быть принят к оплате |
| header | `ZakupayToken` | Да | string | Токен для авторизации пользователя в системе, значение которого можно получить в личном кабинете пользователя на вкладке "Безопасность" в разделе "Токены для приложений, интегрированных с порталом". |

### Успешный ответ

Swagger описывает успешный ответ `200`.

Формат: `application/json`.

Тип ответа: `string`.

### Ошибки и другие ответы

- `400` — Bad Request
- `404` — Not Found
- `403` — Forbidden


## `POST /api/v1/offer/{offerId}/payment-save`

**Название в Swagger:** Создание/редактирование платежа по счету.

**Описание Swagger:**

Метод позволяет создать или изменить платеж.

Пользователь, пытающийся создать или обновить платеж, должен иметь право `OFFERS_PLAN_PAY` или `OFFERS_PLAN_PAY_WITHOUT_NOTIFICATIONS`.

Так же должен быть соблюден ряд условий:
- у пользователя должен быть доступ к счету
- для изменений номера платёжки или, чтобы пометить платеж оплаченным нужно право `OFFERS_PAY` или
`OFFERS_PAY_BY_PREPAID_OFFERS`, или
`OFFERS_PAY_WITHOUT_NOTIFICATIONS`

- чтобы пометить платеж как "принят к оплате" нужно право `OFFERS_PAY_APPROVE` или `OFFERS_PAY_APPROVE_WITHOUT_NOTIFICATIONS`

### Параметры

| Где | Имя | Обязательный | Тип | Описание |
|---|---|---:|---|---|
| path | `offerId` | Да | integer[int64] | Идентификатор счета |
| header | `ZakupayToken` | Да | string | Токен для авторизации пользователя в системе, значение которого можно получить в личном кабинете пользователя на вкладке "Безопасность" в разделе "Токены для приложений, интегрированных с порталом". |

### Тело запроса

Обязательность тела явно не указана.

Формат: `application/json`.

| Поле | Обязательное | Тип | Описание |
|---|---:|---|---|
| `id` | Нет | number | Идентификатор платежа |
| `amount` | Нет | number | Сумма платежа. Должна быть больше нуля и меньше текущей суммы платежа. |
| `amountInMainCurrency` | Нет | number | Валютная сумма платежа. Должна быть больше нуля и меньше текущей суммы платежа. |
| `number` | Нет | string | Номер платёжки. |
| `planPaymentDate` | Нет | number | Дата запланнированного платежа |
| `paymentDate` | Нет | number | Дата факт оплаты |
| `isPaid` | Нет | boolean | Флаг оплаты платежа |
| `accepted` | Нет | boolean | Флаг платежа "принят к оплате" |

### Успешный ответ

Swagger описывает успешный ответ `200`.

Формат: `application/json`.

| Поле | Обязательное | Тип | Описание |
|---|---:|---|---|
| `result` | Нет | boolean | Запрос завершился успешно. |
| `offerPayment` | Нет | object | Информация об измененном/созданном платеже |

### Ошибки и другие ответы

- `400` — Bad Request
- `404` — Not Found
- `403` — Forbidden
