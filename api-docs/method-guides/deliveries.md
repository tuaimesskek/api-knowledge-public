# Доставки

Методы этого раздела сгруппированы по назначению. Для каждого метода указаны контрактные сведения из Swagger; поля и ограничения, которых нет в спецификации, здесь не предполагаются.

Источники:

- `openapi/swagger-core.yaml`

## Кратко по методам

| Метод | Для чего | Как указать объект и данные | Что меняет / возвращает |
|---|---|---|---|
| `GET`<br>`/api/v1/spa/delivery/{id}/facekit` | Отправка доставки в FaceKit | В URL: `id` — ID объекта. | Выполняет действие «отправка доставки в facekit». Ответ: `id`. |
| `GET`<br>`/api/v1/deliveries` | Получение данных реестра доставок | В query: `page`, `pageSize`, `ids`, `offerId`, `include`, …. | Возвращает: `count`, `totalCount`, `page`, `pageSize`, `pagesCount`, `deliveries`. |
| `POST`<br>`/api/v1/deliveries/driver/feedback` | Отправка сообщения от водителя по доставке | В теле: `deliveryId`, `feedbackType`. Заголовок: `ZakupayToken`. | Выполняет действие «отправка сообщения от водителя по доставке». Данные: ID доставки (`deliveryId`); Тип сообещния (`feedbackType`). Ответ: структура успешного ответа не раскрыта. |
| `PATCH`<br>`/api/v1/deliveries/action/accept` | Принятие доставки | В теле: `id`, `deliveryDate`, `deliveryItems`, `offerDocuments`. Заголовок: `ZakupayToken`. | Обновляет: Id принимаемой доставки (`id`); Дата принятия доставки (`deliveryDate`); `deliveryItems`; `offerDocuments`. Ответ: структура успешного ответа не раскрыта. |
| `POST`<br>`/api/v1/deliveries/action/plan` | Планирование доставки | В теле: `transporter`, `plannedDate`, `plannedTransportationDate`, `plannedDeliveredDate`, `plannedDeliveredTime`, `plannedDeliveredDateLimit`, …. Заголовок: `ZakupayToken`. | Выполняет действие «планирование доставки». Данные: `transporter`; `plannedDate`; Дата "доставка запланирована на" (`plannedTransportationDate`); `plannedDeliveredDate`; Ориентировочное время доставки (`plannedDeliveredTime`); …. Ответ: структура успешного ответа не раскрыта. |
| `PATCH`<br>`/deliveries/{id}` | Редактирование данных доставки | В URL: `id` — ID объекта. В query: `plannedDeliveredDate`, `plannedDeliveredTime`, `plannedDeliveredDateLimit`, `plannedDeliveredTimeLimit`, `carModel`, …. Заголовок: `ZakupayToken`. | Обновляет: редактирование данных доставки. Ответ: структура успешного ответа не раскрыта. |
| `POST`<br>`/core/as-built-documentation/deliveries` | Получение исполнительной документации по доставке и доставленным позициям | В теле: `timestamp`, `page`, `pageSize`. Заголовок: `ZakupayToken`. | Выполняет действие «получение исполнительной документации по доставке и доставленным позициям». Данные: `timestamp`; Номер страницы (`page`); Размер страницы (`pageSize`). Ответ: структура успешного ответа не раскрыта. |

Подробные параметры, поля, ответы и ошибки для каждого метода — ниже.

## `GET /api/v1/spa/delivery/{id}/facekit`

**Название в Swagger:** Отправка доставки в FaceKit.

**Описание Swagger:**

Метод отправляет доставку в FaceKit

__Метод доступен если пользователь__:

      - авторизован;

      - имеет доступ к системе;

      - состоит в какой-либо компании;

      - имеет право `DELIVERIES_CREATE`;

### Параметры

| Где | Имя | Обязательный | Тип | Описание |
|---|---|---:|---|---|
| path | `id` | Да | integer[int64] | Идентификатор доставки |

### Успешный ответ

Swagger описывает успешный ответ `200`.

Формат: `application/json`.

| Поле | Обязательное | Тип | Описание |
|---|---:|---|---|
| `id` | Нет | integer[int64] | ID заявки |

### Ошибки и другие ответы

- `400` — Bad Request
- `500` — Internal Server Error


## `GET /api/v1/deliveries`

**Название в Swagger:** Получение данных реестра доставок.

**Описание Swagger:**

Метод позволяет получить список доставок, фильтруя их по набору доступных параметров.
 Выбор доставок производиться только из доступных пользователю, в соответвии с его правами по проектам или по заявкам (исполнитель).

__Метод доступен если пользователь__:

      - авторизован;

      - имеет доступ к системе;

      - состоит в какой-либо компании;

      - имеет право `DELIVERIES`;

| Где | Имя | Обязательный | Тип | Описание |
|---|---|---:|---|---|
| query | `page` | Нет | integer | Номер страницы, данные с которой нужно вернуть. Если не задан, то по умолчанию будет возвращена первая страница данных. |
| query | `pageSize` | Нет | integer | Размер страницы. Максимальное значение 100. Если не задано или задано некорректно, то будет принято как 10 или 100 в зависимости от ситуации. |

| query | `include` | Нет | string | Возможность указать дополнительные параметры запроса.<br> При указании include=orderTemplateInfo в ответ включается информация по шаблону и кастомным полям заявки. |
| query | `updatedTimeFrom` | Нет | string | Возможность отфильтровать доставки по тем, у которых дата изменения доставки равна указанной или позже неё |
| query | `updatedTimeTo` | Нет | string | Возможность отфильтровать доставки по тем, у которых дата изменения доставки равна указанной или раньше неё |

| query | `responsible` | Нет | integer[int64] | Идентификатор `id` ответственного за доставку. Допустимо указывать несколько значений ?...responsible=88544&responsible=47.. |
| query | `orderId` | Нет | integer[int64] | Идентификатор `id` заявки |

| query | `spotDeliveryOut` | Нет | integer[int64] | Идентификатор `id` начального адреса доставки (откуда доставляют) |

## `POST /api/v1/deliveries/driver/feedback`

**Название в Swagger:** Отправка сообщения от водителя по доставке.

**Описание Swagger:**

Метод позволяет отправить сообщение от водителя по поводу его текущей доставки. Тело запроса должно содержать: __ID доставки__ и __тип отправляемого сообщения__: ARRIVED - водитель приехал и ждёт, NOT_ALLOWED - водителю не открывают дверь, LEFT - водитель уехал. </br></br> __Метод доступен если пользователь__:

    - авторизован (имеет токен)
    - имеет право - DELIVERIES

### Параметры

| Где | Имя | Обязательный | Тип | Описание |
|---|---|---:|---|---|
| header | `ZakupayToken` | Да | string | Токен для авторизации пользователя в системе, значение которого можно получить в личном  кабинете пользователя на вкладке "Безопасность" в разделе "Токены для приложений,  интегрированных с порталом". |

### Тело запроса

Обязательность тела явно не указана.

Формат: `application/json`.

| Поле | Обязательное | Тип | Описание |
|---|---:|---|---|
| `deliveryId` | Да | integer[int64] | ID доставки. |
| `feedbackType` | Да | string | Тип сообещния. |

### Успешный ответ

Swagger описывает успешный ответ `204`.

### Ошибки и другие ответы

- `403` — Доставка с указанным id недоступна для пользователя
- `404` — Доставка с указанным id не найдена

## `PATCH /deliveries/{id}`

**Название в Swagger:** Редактирование данных доставки.

**Описание Swagger:**

Метод позволяет редактировать информацию о доставках - период, в который планируется доставить груз,  информацию о водителе, транспорте и компании-перевозчике </br></br> __Метод доступен если__:
пользователь

    - авторизован (имеет токен);
    - владелец токена находится в компании принадлежащей дереву компаний поставщика;
    - имеет право API_EDIT_DELIVERY;

### Параметры

| Где | Имя | Обязательный | Тип | Описание |
|---|---|---:|---|---|
| header | `ZakupayToken` | Да | string | Токен для авторизации пользователя в системе, значение которого можно получить в личном  кабинете пользователя на вкладке "Безопасность" в разделе "Токены для приложений,  интегрированных с порталом". |
| path | `id` | Да | integer[int64] | ID редактируемой заявки |
| query | `plannedDeliveredDate` | Нет | string | Дата начала периода, в который груз может быть доставлен, в формате `'yyyy-MM-dd'`, не может быть позже текущей даты |
| query | `plannedDeliveredTime` | Нет | string | Время начала периода, в который груз может быть доставлен, в формате `'HH:mm'`.</br> Для использования необходимо, чтобы значение **plannedDeliveredDate** было предоставлено в этом или одном из  предыдущих запросов |
| query | `plannedDeliveredDateLimit` | Нет | string | Дата окончания периода, в который груз может быть доставлен, в формате `'yyyy-MM-dd'`.</br> Для использования необходимо, чтобы значения **plannedDeliveredDate** и **plannedDeliveredTime** были  предоставлены в этом или одном из предыдущих запросов. Дата не должна быть раньше, чем **plannedDeliveredDate** |
| query | `plannedDeliveredTimeLimit` | Нет | string | Время окончания периода, в который груз может быть доставлен, в формате `'HH:mm'`.</br> Для использования необходимо, чтобы значения **plannedDeliveredDate**, **plannedDeliveredTime** и **plannedDeliveredDateLimit**  были предоставлены в этом или одном из предыдущих запросов |
