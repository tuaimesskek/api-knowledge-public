Источники:

- `openapi/swagger-edi.yaml`

## `GET /v2/ediStates`

**Название в Swagger:** Получить реестр состояний ЭДО-документов.

**Описание Swagger:**

Пользователь, пытающийся получить список состояний документов в ЭДО, должен иметь право `CUSTOMER_EDI_STATE_REGISTRY` или `SUPPLIER_EDI_STATE_REGISTRY` для работы с реестром состояний документов в ЭДО.

Метод предоставляет возможность запрашивать коллекцию состояний документов в ЭДО постранично, контролируя номер и размер запрашиваемой страницы. Также доступны различные способы по фильтрации состояний<a name="edi-state-update">.</a>

## `POST /edi/send`

**Название в Swagger:** Отправка подписанных или неподписанных документов ЭДО-провайдеру.

**Описание Swagger:**

Метод отправляет документы в систему Эдо-провайдера.

__Метод доступен если__:

- в системе ЭДО-провайдера есть доступ к компании отправителя или получателя;

- в системе ЭДО-провайдера существует возможность обмениваться документами  между указанными компаниями;

- у пользователя есть право `CUSTOMER_EDI_STATE_REGISTRY` ИЛИ `SUPPLIER_EDI_STATE_REGISTRY`;

- у пользователя есть головное право работы с выбранным типом документа. При прикреплении дочерних документов необходимо право головного документа.

`documents[x]` - данные о документе, где х - порядковый номер документа (напр. documents[0]). document[x].content для формализованных документов должен быть в формате json. Для УПД может быть строго в формате по приказу ФНС № 820 (см. https://www.diadoc.ru/docs/forms/upd/structure/8).

В случае загрузки дополнительных документов к __договору оказания услуг__ дополнительно будет проверяться: наличие параметра offerId, существование счёта с заданным offerId, согласованность счёта, совпадение ИНН поставщика в счете и ИНН компании текущего пользователя.

### Параметры

## `POST v1/edi/revoke/{id}`

**Название в Swagger:** Аннулировать документ/ подствердить предложение об аннулировании от контрагента.

**Описание Swagger:**

Аннулирование формализованных и неформализованных документов. Необходимо приложить файл подписи документа __signature__ и файл с предложением об аннулировании __revocation__. Подпись формирует пользователь. Файл с предложением об аннулировании генерируется методом __generateRevocation__.

Метод также используется для подтверждения предложения об
аннулировании, которое поступило от контрагента. В этом случае также необходимо приложить файл с предложением об аннулировании, который генерируется методом __generateRevocation__.

 __Документ не может быть аннулирован, если__:

- Документ уже аннулирован;
- Запрос на аннулирование уже сделан;
- Документу было отказано в подписи;
- Документ черновик/ фейковый документ.

 __Метод доступен если пользователь__:

  - авторизован;
  - имеет доступ к компании с указанным ИНН/КПП;
  - у пользователя есть право `CUSTOMER_EDI_STATE_REGISTRY` или `SUPPLIER_EDI_STATE_REGISTRY`;
  - имеет доступ к ЭДО-документу с указанным ID.
  - имеет доступ к ЭДО-провайдера по указанному логину и паролю

### Параметры

| Где | Имя | Обязательный | Тип | Описание |
|---|---|---:|---|---|
| header | `ZakupayToken` | Нет | string | e.g. <TOKEN_VALUE> |
| query | `id` | Да | integer[int64] | идентификатор документа |

### Тело запроса

Обязательность тела явно не указана.

Формат: `multipart/form-data`.

| Поле | Обязательное | Тип | Описание |
|---|---:|---|---|
| `login` | Да | string | логин пользователя от ЭДО-провайдера |
| `password` | Да | string | пароль пользователя от ЭДО-провайдера |
| `signature` | Да | string[byte] | файл подписи предложения об аннулировании |
| `revocation` | Да | string[byte] | файл предложения об аннулировании документа |
| `powerOfAttorneyUseDefault` | Нет | boolean | значение true означает, что для этого документа используется МЧД по умолчанию, настроенное на стороне пользователя в ЭДО-провайдере. Значение false означает, что МЧД будет передано по ИНН доверителя и регистрационному номеру доверенности. Если значение в запросе отсутствует, то МЧД не используется. |
| `powerOfAttorneyIssuerInn` | Нет | string | ИНН доверителя из МЧД. Значение используется для передачи МЧД по fullId(https://developer.kontur.ru/docs/diadoc-api/proto/PowerOfAttorneyFullId.html). Первая часть fullId. Должен указываться вместе с powerOfAttorneyRegNum и powerOfAttorneyRepresentativeInn. |
| `powerOfAttorneyRegNum` | Нет | string | регистрационный номер МЧД. Значение используется для передачи МЧД по fullId(https://developer.kontur.ru/docs/diadoc-api/proto/PowerOfAttorneyFullId.html). Вторая часть fullId. Должен указываться вместе с powerOfAttorneyIssuerInn и powerOfAttorneyRepresentativeInn. |
| `powerOfAttorneyRepresentativeInn` | Нет | string | ИНН представителя из МЧД. Значение используется для передачи МЧД по fullId(https://developer.kontur.ru/docs/diadoc-api/proto/PowerOfAttorneyFullId.html). Третья часть fullId. Должен указываться вместе с powerOfAttorneyIssuerInn и powerOfAttorneyRegNum. |

### Успешный ответ

Swagger описывает успешный ответ `200`.

Формат: `application/json`.

| Поле | Обязательное | Тип | Описание |
|---|---:|---|---|
| `result` | Да | boolean | Запрос завершился успешно. |
| `ediStates` | Нет | object | Описание аннулированного ЭДО-документа |

### Ошибки и другие ответы

- `400` — Bad Request
- `401` — Unauthorized
- `403` — Forbidden
- `404` — Not Found
- `500` — Internal Server Error


## `POST v1/edi/{id}/generateRevocationRejection`

**Название в Swagger:** Отказать в предложении об аннулировании.

**Описание Swagger:**

Позволяет ответить отказом на предложение об аннулировании ЭДО-документа, отправленное контрагентом. В предложении об аннулировании нельяз отказать, если контрагентом не было отправлено предложение об аннулировании;


 __Метод доступен если пользователь__:

- Авторизован;
- Имеет доступ к системе;
- Состоит в какой-либо компании;
- У пользователя есть право `CUSTOMER_EDI_STATE_REGISTRY` или `SUPPLIER_EDI_STATE_REGISTRY`;
- Имеет доступ к ЭДО-документу с указанным ID.

### Параметры

| Где | Имя | Обязательный | Тип | Описание |
|---|---|---:|---|---|
| path | `id` | Да | integer[int64] | ID ЭДО-документа. |
| header | `ZakupayToken` | Нет | string | e.g. <TOKEN_VALUE> |

### Тело запроса

Обязательность тела явно не указана.

Формат: `multipart/form-data`.

| Поле | Обязательное | Тип | Описание |
|---|---:|---|---|
| `login` | Да | string | логин пользователя от ЭДО-провайдера |
| `password` | Да | string | пароль пользователя от ЭДО-провайдера |
| `certificate` | Да | string[byte] | сертификат пользователя в DER кодировке |

### Успешный ответ

Swagger описывает успешный ответ `200`.

Формат: `application/xml`.

Тип ответа: `string`.

### Ошибки и другие ответы

- `303` — See Other
- `400` — Bad Request
- `401` — Unauthorized
- `403` — Forbidden
- `500` — Internal Server Error
- `404` — Not Found
